# Changelog

All notable changes to Nonfiction Studio are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project uses [Semantic Versioning](https://semver.org/) once a version is tagged. See `MIGRATION.md` for what counts as a breaking change to a book already in progress, and `RELEASE-NOTES.md` for curated, user-facing summaries of each release.

This file is written from the commit history of the branch it ships from, not from a plan or a roadmap: an entry here means the change actually landed, not that it was intended.

## Unreleased

### Added

- **Wave 1 exit** (ADR-0013, wave 1 exit surfaces), closing roadmap rows 1.8 and 1.10, the last two rows of Wave 1, in eight pieces:
  - A per-project settings file, `.claude/nonfiction-studio.local.md` (`hooks/lib/settings.mjs`, OPP-P11 per-project studio settings): a YAML-frontmatter-fenced schema v1 (`gate_mode`, `thresholds`, `routing_enforce`, `output_style`), found by walking up from the current directory the same way the book root itself is found. Corruption is warn-and-default at two granularities: a whole-file failure (unreadable, no frontmatter fence, invalid YAML, or non-map frontmatter) yields empty settings and one warning sentence; a per-key type or enum failure drops only that key, keeps every valid sibling, and names the dropped key in a `droppedKeys` array. `hooks/lib/gate-engine.mjs`'s `loadGateConfig` overlays `gate_mode` onto the top-level `gate.mode` and shallow-merges `thresholds` over `config.json`'s own, strictly before the D-03 (layered Stop gate) structural coercions - a settings file can raise gate strictness but can never un-coerce `thesis_alignment` or `quote_fidelity` back to blocking, because the settings schema has no per-check mode key for the coercion to be bypassed through. `docs/formats/settings.md` is the normative page.
  - Two output styles, `manuscript` and `review` (`output-styles/`, OPP-P17), shipped as a new plugin component class: prose-first drafting responses and terse verdict-first tabular responses, respectively. `nfs-new-book` offers a consented choice once per project; neither is ever forced (`force-for-plugin` is unset on both). A live platform probe found that activation requires the **namespaced** settings value `nonfiction-studio:<style name>` - a bare frontmatter name, a bare filename slug, or a wrong-casing namespaced form all silently fail with no error - so the offer composes and writes this exact value into the project's own `.claude/settings.local.json` on explicit consent, merging rather than overwriting. This is a second, project-scoped consented-write path alongside the `doctor` skill's pre-existing, still-sole USER-scope write (the one-time statusline install); see `docs/reference/output-styles.md`.
  - `SessionStart` gains `initialUserMessage` (OPP-P12 zero-friction first session) and `reloadSkills`, both nested under `hookSpecificOutput` per a live probe (a top-level placement is silently ignored). `initialUserMessage` opens the studio dispatcher unprompted, but only when no book project is found and the directory is truly empty (an allowlist guard against hijacking an unrelated project's first turn). `reloadSkills` fires when a generated project `book-context` skill exists (see the next item). The same-session-liveness half of this acceptance criterion is adapted, not met: a skill written mid-session is invocable only starting the next session or a resume, confirmed by probe, and every document describing the feature says so.
  - `nfs-new-book` can generate a project-committed `book-context` skill at `.claude/skills/book-context/SKILL.md` (OPP-P12 zero-friction first session): a quick-reference assembled from the bible content at generation time - thesis one-liner, top three style rules, chapter map, and open-claims count - each line naming the file or CLI it was read from. Generated only on an explicit yes; declining, or running in a non-interactive session, writes nothing, and the offer repeats on a later `nfs-new-book` run only while the file remains absent. See `docs/privacy.md` for what it contains and how to remove it.
  - Chat-surface compliance parity (OPP-P09): the six agent-dispatching skills (`nfs-capture-voice`, `nfs-draft`, `nfs-fact-check`, `nfs-interview`, `nfs-outline`, `nfs-research`) now carry a byte-identical verify-then-append compliance stanza, checked for byte-identical presence by a new Tier A checker (`scripts/checks/check-compliance-stanza.mjs`) that derives the dispatching-skill set from each skill's own frontmatter `chain:` list rather than a hardcoded roster. A skill counts existing `ai-use-log.jsonl` records targeting each file it is about to write, re-counts after writing, and appends its own record only when the count did not increase - so a hook-backed surface never gets a duplicate. `ns-doctor` gains a twelfth check reporting per-chapter "uncovered writing window" notices and the exact coverage fraction; the fraction lives on the doctor report because the disclosure-report skill that would otherwise host it is Phase 2, unshipped.
  - `ns-overlap`, the ninth shipped CLI, and its engine (`hooks/lib/overlap-engine.mjs`, OPP-D10 local overlap check): local n-gram overlap detection between chapter prose and an author's own research corpus, with no network access. The corpus is every file in `research/packets/*.md`, every non-empty `verbatim` field in `research/evidence-log.md`, and (when present) every file in `context/prior-work/*.md`. Both the chapter text and every corpus text are normalized identically (Unicode NFC, case-fold, typographic-to-straight quotes, whitespace-run collapse) before an 8-word shingle comparison chains matching shingles into maximal spans; a merged span of at least 15 words (overridable via `thresholds.overlap_min_words` or the CLI's `--min-words`) is a finding naming both locations. A chapter span sitting inside a properly quoted-and-anchored passage is excluded as already attributed, reusing the claims engine's own quoted-span helper, and that exclusion is reported as an informational count rather than dropped silently. `overlap` also registers as the seventh gate check, warn-mode by default and, unlike `quote_fidelity` and `thesis_alignment`, not structurally coerced - it is fully deterministic, so an author can opt it all the way to `block` via the normal double opt-in. The gate check calls the identical `findOverlaps`/`discoverCorpora` functions the CLI does, so the two can never compute overlap differently, satisfying two of D-05 (five shipped CLIs)'s three growth-policy questions. Ships with `docs/reference/cli/ns-overlap.md` and a fixture set at `tests/engines/fixtures/overlap/`.
  - Model-tier and chain-edge enforcement at agent dispatch (`hooks/pre-tool-use.mjs`, D-18 in-plugin model routing, OPP-P05 routing enforced at dispatch): dispatching a plugin agent (`nonfiction-studio:<slug>`, matched on a `tool_name` of `Agent` or `Task`) with an explicit model override that disagrees with the agent's own declared `model:` frontmatter now warns, citing both the declaration and the request; an agent declaring `model: inherit` never warns on model, and omitting the override entirely stays silent, since the platform then resolves to the declaration anyway. `agents/_chain-permitted.yaml`, previously enforced only at lint time, is now also a runtime contract: when the dispatching context is itself a plugin agent, dispatching a further agent along an edge that file does not list warns, naming both agents; a main-session dispatch never triggers this chain check. No separate routing-registry file was built - both rules read `agents/<slug>.md` frontmatter and `agents/_chain-permitted.yaml` directly, on demand, rather than duplicating either into a new file that could drift out of sync. Both checks default to a warn-only `additionalContext`; the settings file's `routing_enforce` key (`off`, `warn`, or `block`) can turn a warning into a deny with the identical wording, or silence the branch entirely. A settings-file problem silences this branch only on a whole-file failure or when `routing_enforce` itself is the individually dropped key; a warning naming a different, unrelated key no longer silences a validly configured `routing_enforce` - a narrower rule adopted after a live review reproduced the broader rule letting an explicitly configured `routing_enforce: block` go silently dark beside an unrelated typo elsewhere in the same file.
  - Both shipped config templates (`templates/config-defaults.json`, `templates/book-scaffold/.studio/config.json`) are now proven, by a gate-suite parity test, to carry exactly `DEFAULT_GATE.checks`'s key set, closing PF-28 (config template divergence): the divergence was latent, not live, since `loadGateConfig` already merged from `DEFAULT_GATE` for any check name a template omitted.

### Changed

- All fourteen skills renamed to the `nfs-` prefix convention, closing PF-02 (short skill names) and PF-03 (quality gate skill name): `build-apparatus` to `nfs-build-apparatus`, `capture-voice` to `nfs-capture-voice`, `doctor` to `nfs-doctor`, `draft-chapter` to `nfs-draft`, `fact-check-pass` to `nfs-fact-check`, `init-project` to `nfs-new-book`, `intake-interview` to `nfs-interview`, `outline-book` to `nfs-outline`, `quick-scan` to `nfs-quick-scan`, `research-pass` to `nfs-research`, `run-quality-gate` to `nfs-check-chapter`, `status-dashboard` to `nfs-status-dashboard`, `studio` to `nfs-start`, and `tour` to `nfs-tour`. A skill's short invocation form shares a namespace with every other installed plugin, and most of these names were ordinary enough words or phrases that any other plugin could plausibly claim them first; the house convention across sibling plugin libraries is to prefix for exactly this reason. Four names also improve on the original rather than merely prefixing it, because the old name no longer named the job well: `run-quality-gate` becomes `nfs-check-chapter` and `init-project` becomes `nfs-new-book` because those are the words an author actually reaches for, `intake-interview` becomes `nfs-interview` for the same reason, and `studio` is renamed rather than prefixed to `nfs-start` because `nfs-studio` would stutter (`nfs` already expands to non-fiction studio) and exempting the single most collision-prone name in the set from the convention would defeat the point of adopting it. All eight fake verb-alias clauses (`/draft`, `/factcheck`, `/book-init`, `/interview`, `/outline`, `/research`, `/gate`, `/status`) are deleted from every SKILL.md's frontmatter and reference page, closing PF-05 (verb aliases) and PF-11 (verb aliases unregistered): this plugin ships no `commands/` directory, so none of these was ever a registered command to migrate, only documentation shorthand, and the new short skill names are now the typeable verbs themselves. Recorded in ADR-0003 (skill invocation ergonomics)'s dated amendment. See `MIGRATION.md` for the full old-to-new invocation table.
- `README.md` rewritten as a full front page, replacing the 63-line placeholder: hero block with badges and section navigation, a table of contents, marketplace-first install instructions for the `prisant-labs/agent-plugins` catalog, the six quality-gate checks explained with a diagram of the governed loop, and a complete catalog of every shipped skill, subagent, and CLI with a description of each. The Surfaces table, the self-sufficiency statement, the privacy note, and the MIT-plus-Apache-2.0 license split carry over unchanged in substance, including the Cowork caveat, which stays as written until SPK-02 (Cowork execution spike) runs per ADR-0002 (Cowork hook execution). Component counts in the new text are the ones `scripts/checks/check-component-counts.mjs` enforces; no unenforced count was introduced.
- Six skill verb triggers rephrased from "legacy" framing (implying a deprecated slash command) to "alias" framing (this plugin has no `commands/` directory at all, so no verb was ever a registered command to deprecate) - F4 (verb vocabulary).
- The Stop hook's check list now derives from the quality gate engine's own registry instead of a separately hand-maintained copy, and a third duplicated `foldForCompare` implementation was collapsed into the shared module.
- Self-sufficiency scanning closed blind spots in its scanned-file set (`examples/` was previously unscanned for provider-key patterns) and gained negative tests proving each checker can genuinely fail on a planted violation, not only pass - F6 (checker negative tests), F7 (scan-set blind spots).
- A second detector, `scanPromptInjection`, was built to flag instruction-override phrasing directed at an assistant in fetched web content, then adversarially tested and removed across four review rounds: every narrowing tried, down to its tightest form, false-positived on realistic content in the exact domains the untrusted-fetch hook scans (support FAQs, changelogs, security blogs, and ordinary developer documentation), because pattern matching could not separate an imperative addressed to an assistant from the same words used to describe, report, or instruct a human reader. This hook does not attempt instruction-override detection, by deliberate decision, not oversight; the unconditional wrap and fence remain the actual defense regardless of scanner findings, per AR-07 (security, privacy and safety) and D-13 (security posture).
- Stylometry drift scoring corrected: `type_token_ratio` is now a length-invariant moving average over 100-token windows instead of a flat ratio that fell monotonically as text grew, and no single marker's contribution to the drift score may exceed one third of the configured budget (`MARKER_CONTRIBUTION_DIVISOR`), so a single near-zero-baseline marker can no longer decide a verdict alone.
- The default drift budget (`DEFAULT_DRIFT_SCORE_MAX`) recalibrated from 35 to 25 against the new labeled scenario suite, closing a gap where a chapter stripped of every contraction and every first-person pronoun (the canonical ghostwriting signature) passed at the old default. Every scaffolded book carries an explicit `thresholds.drift_score_max`, so only a book that omits the key from `.studio/config.json` sees the new default.
- A stylometry baseline now carries a `stylometry.baseline.marker_set_version` field; `computeDrift` refuses to score a baseline captured under a different marker set version, raising a named `StaleBaselineError` that names `nfs-capture-voice` as the remedy. `bin/ns-stylometry --measure` emits the version alongside the marker vector so the capture path carries it by construction.
- The voice verdict is now the largest standardized deviation (max `|z|`) against a null calibrated from the author's own voice corpus, replacing the capped-sum rule ADR-0011 (tranche 2 decisions) set: that rule was measured, on ADR-0012 (voice verdict scope)'s own probe, to discriminate a planted ghostwriting signature from ordinary chapter-to-chapter voice variation at AUC 0.53 on real prose - a coin flip. Each marker's deviation is standardized against a per-marker noise scale read from a five-rung calibration ladder (`spans: [550, 1100, 2200, 4400, 8800]` words, log-linear interpolation between rungs, clamped beyond either end), and the threshold is the stored empirical 0.99 null quantile at that same word count - never an assumed constant. `marker_set_version` moves to 5; a v4 baseline is rejected outright, with recapture via `nfs-capture-voice` as the only remedy (every book needs a fresh baseline before this release's gate can score any of its chapters again). The gate's stylometry check is now two-tier and regime-aware (ADR-0012 Decision 2): capture measures detectability (the ghostwritten-vs-honest AUC at the shortest rung against a 0.95 bar) and assigns `"chapter"` or `"book"` regime accordingly. Chapter regime scores and blocks each chapter individually, skipping stub or empty chapters under 50 scorable words as advice; book regime blocks on the aggregate alone, and only once it reaches 2,200 scored words - below that floor the check reports pass-with-advice and never blocks. The gate report's `stylometry` check entry gains a structured `drift` sibling to `detail` (`{ regime, statistic, threshold, worst_marker, worst_chapter, per_chapter, skipped }`), closing PF-14 (structured drift field) - a consumer no longer has to parse the statistic and threshold out of prose. `bin/ns-stylometry` gains `--calibrate` (runs the five-rung calibration recipe over a voice corpus, refusing under 2,200 usable words), `--by-register` (advisory-only comparison against author-labeled register buckets configured in the new `stylometry.registers`, verbatim-labeled so it is never mistaken for a blocking verdict), and passage attribution in `--explain` (the worst marker's most locally deviant 100-token window, reported as a 1-indexed word-offset range) - closing roadmap row 1.7 (voice registers) on honest terms. `nfs-capture-voice` is now computational (PF-25, voice-capture write contract, closed): the agent persists every writing sample under `context/samples/` before calibrating, then writes the full v5 baseline (`markers`, `marker_set_version`, `calibration`, `captured`, `sample_count`, and a one-sentence `method` provenance field) via read-modify-write, and discloses the calibration cost and the resulting regime in plain language before and after the run. A new independent voice corpus (`examples/sample-book/context/samples/voice-corpus-01.md` through `-03.md`, three files, ~3,500 words, disjoint from the two scored chapters) calibrates the shipped sample book's baseline; its sparse first-person voice lands it honestly in the book-scale regime, which is the demonstration, not a defect. `examples/fixtures/voice-drift` becomes the chapter-regime demonstration fixture instead, with its own calibrated author voice and its own independent corpus, planted to block per chapter. `thresholds.drift_score_max` is retired: it is readable but ignored for one release (a config that still sets it draws a one-time deprecation notice, once in the gate check's `detail` and once on `ns-stylometry`'s stderr, before becoming an error in a future release); `MARKER_CONTRIBUTION_DIVISOR` is gone outright. `thresholds.stylometry_marker_tolerance` (the advisory per-marker flag band) is unchanged.

### Fixed

- `skills/nfs-new-book/SKILL.md` Step 6 restated the plugin version as a literal `0.1.0`, both for the `{{PLUGIN_VERSION}}` substitution and in the illustrative `.studio/meta.json` block: the same defect class PF-23 (stale version literal) named, a shipped instruction copying a value a manifest owns.
